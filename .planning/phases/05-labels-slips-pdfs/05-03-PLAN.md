<objective>
Ship `download_slip` (MISS-06 → `GET /slips/{slipType}?order_ids=...` on the Platform host). This is the THIRD and final tool of Phase 5 and the first one that does NOT live on the Quiqup-GraphQL-host introduced by Waves 1-2 — it lives on the existing Platform host (`platform-api.quiqup.com`).

The endpoint requires TWO non-default headers the existing `lib/clients/platform-api.ts` does not forward: `api-version: 20180108` AND `Accept: application/pdf` (the client's default `Accept: application/json` would 406 a PDF response). To support this WITHOUT forking the client, extend its `request()` method with an OPTIONAL `extraHeaders` parameter. The extension is deliberately small and backwards-compatible: every existing caller (Phase 1-4 tools, ~30 call sites) continues to work unchanged.

The same `extraHeaders` mechanism will be needed by Phase 8 SHIP-02 (`list_carrier_capabilities`) for its `x-api-version: 20240101` header (source-doc §11 line 499). Doing the work here means Phase 8 inherits a tested mechanism instead of repeating the extension itself.

Two structural details distinguish this tool from Waves 1-2:
  1. The Platform host (not Quiqup-GraphQL-host) means a different client (`PlatformApiClient`) and a different error class (`QuiqupHttpError`, the existing one — Platform is an existing host family per STATE.md "sibling clients of an existing host family reuse the existing class").
  2. `slipType` is enum-bounded (`"picking-list" | "packing-list"`) per source-doc — the LLM cannot probe undocumented slip types.

Output: client extension (backwards-compatible), 1 new tool spec, extended client + tool test files (no new test files), `app/[transport]/route.ts` registering the new spec, the tool-surface snapshot bump, AND a `CALL-LOG-download-slip.md` capturing the AGENTS.md-mandatory live-staging call.
